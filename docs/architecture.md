# 实现与边界

单个中心服务处理群消息、MCP 和 Runner HTTP API；它持有 `agent-collab` Git 独立 worktree，串行追加版本化事件。每位同事在自己的设备配置个人 MCP/Skill，选择性启动 Runner 领取由服务按用户分配的工作；Runner 为每个任务在本地创建独立 Git worktree 与 Codex SDK 会话。代码在 `codex/task-*` 分支，任务事件在 `agent-collab` 分支，两者不相互合并。群消息仅为结构化任务指令和状态摘要，**不共享原始私聊记录**。群内显示的是一个 Bot 代表不同账号的消息，不是真实的多个独立聊天机器人。

消息路径：飞书/企微消息 -> 允许的群 ID 与平台用户 ID（飞书 open_id / 企微 userid） -> 命令解析 -> 服务权限检查 -> Git 提交 -> Bot 回复。任务路径：分配 -> Runner 领取 -> worktree 编码/提交/可信测试 -> 审查请求 -> 审查 Runner/人工审核 -> 管理员完成。`read_task` 和 `list_tasks` 可让同事桌面 Codex 人工参与；不会唤醒任意已开的桌面会话。

限制：仅支持单写服务，没有集群式 CAS、持久消息投递队列、续租/心跳、失败后自动恢复或 Git push 冲突重放。默认 localhost；远程接入必须自行部署 HTTPS 和访问限制。飞书或企业微信智能机器人长连接需应用权限、群和成员 ID；企微使用出站 WebSocket，无公网回调。企微尚待新凭据和真实群验证；两种通道都不能只以认证成功代替群收发验证。代理执行陌生仓库代码仍有风险，应在低权限容器隔离。
