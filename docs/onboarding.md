# 团队安装与首次接入

管理员统一创建企业微信机器人、分配职责，再把加密个人接入包交给同事。成员不需要自行创建机器人、手工查群 ID/用户 ID，也不需要单独部署中心服务。每个人的本机工具直接通过共同的 Git remote 协作。

## 每个人先准备一次

1. 安装 Node.js 20+、Git 和支持对话 heartbeat 的 Codex 桌面应用。
2. 确认业务仓库至少有一个远程业务分支（如 `main`、`master`、`develop`），本机 Git 凭据能读取并 push `agent-collab` 及任务代码分支。已有独立 clone 可以直接使用；没有 clone 时让向导从 Git 地址拉取。
3. 打开终端执行。已有项目时可先进入项目目录，让向导自动带入信息；没有本机 clone 时也可直接启动：

```sh
npm install --global --foreground-scripts xuym-codex-collab
codex-collab setup
```

安装完成后会提示运行 `codex-collab setup`；`--foreground-scripts` 用于显示 npm 默认可能隐藏的安装脚本输出。使用 `--ignore-scripts` 或没有看到提示时，仍可直接运行该命令。安装过程只显示提示，运行 `setup` 后网页自动打开；若未打开，执行 `codex-collab setup --no-open`，复制终端打印的本机链接。工作台已在后台运行，可以关闭终端和浏览器。macOS 默认设置登录自启，Linux 尝试设置 systemd 用户服务；未配置成功时页面和终端会明确提示。手动停止的连接不会在登录或后台检查时重新启动。团队成员无需 clone 工具仓库。也可执行 `npx xuym-codex-collab@latest setup` 临时打开向导；长期运行推荐全局安装，以便登录服务使用稳定安装路径。

同一台电脑模拟两位成员时，使用同一业务仓库的两个独立 clone、两个机器人、两个 Codex 对话；同一个 clone 只能接入一个身份。同一个企业微信账号可以拥有多个 Agent，每个 Agent 的机器人、签名身份、clone 和对话独立。真正同事使用自己的企业微信账号和 Git 凭据。

## 在项目里管理机器人

首页“我的项目”按协作远程仓库与签名团队身份汇总。同一项目的不同 clone、不同远程别名及 HTTPS／SSH 地址会归到同一项目；fork 或不同签名团队继续分别展示。已有接入自动聚合，无需重新导入。

打开项目后只有一份“项目机器人”列表，包含自己的和同事的机器人。自己的标记“我的”；标记依据本机签名身份与团队已验证的所有者关系，同一已验证账号的其他机器人也会标记。本机没有接入的机器人会明确提示；同事的机器人展示角色和职责，不推测远端机器是否在线。

本机已接入的机器人显示实际连接状态，点击“查看”或“完成连接”打开原接入详情，随后可“返回项目”。项目中的“团队与邀请”和“添加我的机器人”对已验证且就绪的本机管理员显示。普通成员拥有多个机器人时继续通过管理员分配的独立接入包接入。

首页读取本机接入记录；项目页先显示本机签名校验通过的团队记录，再同步远程账本。同步失败保留已验证记录并提示重试。归属标签只用于展示，操作仍检查对应身份的既有权限。

页面采用居中、逐步接入的布局，每屏只处理一个动作；项目、机器人、群验证和对话绑定之间有轻量过渡，不加载外部字体或动画库。页脚可切换纸白、雾绿与夜色。动画使用 `transform` 和 `opacity`；页面进入后台时暂停动画与项目自动同步请求，系统开启“减少动态效果”时关闭动画与过渡。

## 管理员操作

1. 在企业微信创建独立智能机器人，获取 Bot ID 和 Secret，拉进协作群。为每位成员分别创建机器人并加入同一个群；真人同事也加入群。
2. 选择“接入一个项目”。当前目录属于 Git 项目时会自动带入项目根目录，并带入本机用户名。确认项目，或选择 Git 地址拉取新目录（目录可留空自动生成），点击“继续”。向导会检查项目并推荐验证命令；需要修改时展开“分支与验证方式”，例如 `npm test`、`go test ./...` 或 `sh test.sh`。未识别到验证命令时会展开选项，要求填写后再继续。工具自动识别协作远程与远程默认分支；多个不同远程或默认分支不明时，页面要求选择一次，也可主动选择其他基准分支。检查只读取常见测试入口，不执行项目脚本；实际任务使用确认后的固定程序与参数，不支持管道或命令拼接。
3. 输入自己的 Bot ID/Secret，点击“连接机器人”。显示名称与主要职责在折叠选项中调整；名称可以是 `Alice` 或“张三”，内部 Agent ID 自动生成，也可自定义身份和标签。
4. 用自己的企业微信账号 @ 此机器人，发送页面显示的 `协作 接入 六位数字`。页面自动发现群 `chatid` 与本人 `userid`，创建身份、签名账本，配置项目 MCP/Skill 并启动本机机器人 Runner；无需再点击继续。群验证中刷新页面可以恢复进度。
5. 从项目页点击“团队与邀请”，找到“批量分配机器人给同事”。每行填写显示名称、选择职责、填写独立机器人的 Bot ID/Secret，点击“增加一位成员／机器人”添加更多行。默认设为该职责的首选执行者并允许所有者群命令；候补与自定义 ID/职责在折叠选项中调整。一次最多 25 行。
6. 点击“生成全部接入包”。密码自动生成；在“已分配的机器人”逐个下载加密 JSON 文件、查看并复制接入说明。把文件和说明交给指定成员，密码通过另一条可信渠道单独发送。说明不包含密码或 Secret。包默认 7 天有效，同一成员或机器人不会同时分发多个有效邀请；重复 ID/Bot 的批次会在发布前拒绝。
7. 成员群验证后，“待确认的成员”自动出现申请。核对内部 Agent ID、职责和 userid，明确点击“确认此成员入队”。成员页面自动等待批准并继续配置；批准不会由向导替你做。新的签名策略通过 Git 同步到其他在线成员。
8. 管理员也按下文把自己的 Codex 对话启用。需要调整审核人时，展开“团队分工、审核与通知设置”，默认阶段审核由执行 Agent 的本人处理；可选管理员或已验证身份的同事。

同一位同事可以领取多行分配，用同一个企业微信账号分别验证不同机器人；每份包选择独立 clone，并绑定不同 Codex 对话，不需要关闭群命令权限。

### 协作远程与任务基准分支

不要求远程名为 `origin`，也不要求有 `main`。管理员选好项目后，工具读取远程的实际默认分支；只有多个不同仓库地址或无法确定默认分支时才需要选择。不能把 `agent-collab` 账本分支作为业务基准。所选远程的拉取和推送地址必须指向同一仓库；同仓库的 HTTPS 拉取、SSH 推送可以配合使用。

远程别名属于各自的本机配置：你的 clone 可以叫 `origin`，同事可以叫 `upstream`。成员接入时按邀请中的仓库地址匹配远程，不需要改别名；如果另有个人 fork，不会误选它。团队基准分支写进管理员签名的策略，成员和新增机器人自动继承。每个机器人继续使用独立 clone 和 Codex 对话。

管理员在项目页点击“团队与邀请”，再展开“团队分工、审核与通知设置”，点击“读取并调整基准分支”即可切换到已有远程业务分支。修改通过签名版本链同步，只对之后创建的任务生效。已有任务保留原基准分支、创建时的完整 commit SHA、分工与审核规则。修改与其他管理员操作冲突时，重新读取后再保存。

新任务在创建时从团队远程基准分支固定起始 SHA。排队期间分支继续提交，首次领取和失败后的候补仍从这个 SHA 开始；阶段接力从上一阶段已验证的精确提交继续。创建快照使用私有账本 clone，不改变业务工作区、当前分支或它的 `FETCH_HEAD`。如果远程基准分支被删除、强制改写为不包含起始 SHA 的历史，或无法读取所需提交，任务会报错；不会自动换成最新代码。应先恢复可读历史，或明确终止旧任务并创建新任务。

**升级到 0.6.0 时，全员先升级工具并重启工作台、机器人 Runner 和项目 MCP，再创建新任务。** 新任务使用 v3 规格（增加 `base_commit`）；旧客户端无法读取。历史 v2 任务继续按原签名策略重放，不会补写 SHA 或改动业务分支。旧团队没有显式基准时仍按 `main` 处理，需要管理员在上述设置中调整。

### 接入包密码遗失

接入包经过加密；旧版本若没有保存单独生成的密码，不能从密文或旧 JSON 中还原。管理员可为尚未批准的成员重新签发：

1. 先让团队所有成员把工具升级到 `0.4.3` 或以上，并重启 Runner 与 MCP。旧客户端对新签名版本会拒绝继续，不能在同一个团队里混用旧版本。
2. 在管理员项目的“已分配的机器人”中，打开对应成员的“查看接入说明与密码”。如果显示密码缺失，点击“重新生成接入包与密码”。
3. 页面会预填原 Bot ID；管理员在本机输入该机器人的 Secret。工具保留原 Agent 与职责，生成新加密文件和新密码，并在 Git 签名版本链中撤销旧邀请。Secret 不会发到聊天或写入 Git。
4. 通过可信渠道分别交给成员新接入包和新密码。旧文件以及基于旧包创建、尚未批准的申请都不能再使用。
5. 成员在“接受同事的邀请”选择 Bob 原来的本机 clone，上传新包并输入新密码，选中文件并填完密码后点击“继续”，核对下一屏展示的接入信息和项目目录后再接入。工具会在确认签名替换关系后复用该 clone 的本地身份记录，清除旧申请并要求重新验证群身份；管理员随后确认新申请。

该恢复入口仅用于未批准的普通成员邀请。已获批准的成员不能重签，应继续使用已有本机配置；管理员自己的机器人也不使用分发包恢复流程。若 Git 发布中断，半成品不会显示为可下载包；回到原邀请重试生成即可复用同一恢复记录。

显示名称保存在本机和加密接入包中；团队签名和群协议仍用内部 Agent ID。真人通过自己的企业微信账号验证接入，以便核对审核权限；额外通知对象不会因此获得审核权限。

机器人应在企业微信后台设为多人可用，并把实际协作成员加入可使用范围。平台允许使用后，工具还会核对发言人的 `userid` 是否属于已批准入队的成员；成员可以 `@` 任意团队机器人提交需求、创建任务或查询状态。审核、取消、完成等操作仍按任务和本人权限限制。未完成团队接入的群成员不能派发任务。

机器人必须由一个本机 Runner 保持连接。同一个 Bot ID 不要同时运行旧服务、群发现命令和新 Runner。向导检查可识别的本机重复连接；其他电脑上的连接需由团队核实。

## 成员操作

1. 从管理员取得自己的加密接入包、接入说明和单独发送的密码，打开 `codex-collab setup` 或 `npx xuym-codex-collab@latest setup`，选择“接受同事的邀请”。
2. 选择接入包文件、输入密码，点击“继续”。下一屏会展示团队、Agent、职责、仓库和建议目录；默认“帮我拉取到新目录”，可修改保存路径，也可切换“使用本机已有项目”。确认后点击“接入项目”。工具先验证接入包再 clone，使用本机 Git 登录；已有项目必须属于包内同一 remote，支持同一仓库的 SSH/HTTPS 表达。
3. 用**自己的企业微信账号** @ 分配给你的机器人，发送页面验证码。页面自动生成签名身份，把带公钥的入队申请写进协作分支，并进入等待批准；无需返回点击确认。刷新页面可以恢复当前验证或申请进度。
4. 管理员明确批准后，页面自动检查 Git 权限、写入项目本地 MCP 和 Skill、启动机器人连接。正常流程无需点击“继续接入”；Git/配置异常时会停在可恢复的步骤，处理后再明确重试。
5. 在 Codex 打开页面上的业务项目，信任项目并加载 MCP/Skill。点击“复制启用指令”，粘贴到要代表你的**已有对话**，例如：

```text
使用 $team-collab-desktop，启用当前项目的团队协作，将 bob 机器人绑定到当前对话。项目：项目绝对路径
```

6. Skill 完成身份核对、绑定真实 thread ID、复用或创建该对话的 heartbeat，并立即做一次轮询。工作台自动更新状态；展开“查看连接详情”确认机器人认证、对话绑定和实际轮询。

启用指令不是 Secret。成员无需手工编辑 JSON、生成密钥或复制 userid；无法识别 Skill 时可展开详细指令作为备用。Codex 若没有暴露真实对话 ID，仍需本人提供该对话 ID/链接；工具不会猜测或访问应用私有数据库。若应用不支持 heartbeat，Skill 会明确说明尚未启用自动轮询，不能仅凭已绑定就认定能接单。

工作台后台检查只在页面打开时推进向导进度；已经启动的 Runner 和已启用的对话 heartbeat 独立运行。关闭工作台后重新打开，可以从首页继续，不需要重建成员身份。

## 已有 Alice/Bob 配置如何迁移

现有通过私有 `peer.json` 运行的项目无需重新生成身份或重绑对话。

1. 用原配置停止该机器人的 Runner：`codex-collab stop /absolute/path/to/private-peer.json`。有正在执行的任务时先处理其租约/执行状态。
2. 在网页首页展开“其他接入方式”，选择“导入已有配置”，填写原私有配置的完整路径。**旧团队由管理员先导入，然后其他成员分别导入**。
3. 工具从原策略建立签名版本根，保留原身份、私有数据目录、Codex 对话绑定和任务，再通过原配置路径重启 Runner。
4. 向导刷新可识别的项目 MCP 和 Skill；重新加载 MCP，再把页面的新启用指令发送到原绑定对话，更新原 heartbeat 的提示词。以后统一在工作台查看状态、添加新成员。
5. 原 v2 团队不会仅因导入就改变接力行为。所有成员更新工具并重启机器人和 MCP 后，管理员在“真人审核与通知”保存规则，发布 v3 策略。此后创建的新任务应用新规则；正在执行的旧任务继续遵循原策略。

向导只更新工具生成且可识别的 Skill/MCP；自定义、已提交或不同身份的配置需要本人手动检查。原对话绑定和其他模型/provider 配置保留。仅升级 npm 工具不足以更新已经复制进项目的 Skill 或应用 heartbeat；也可按 [自然语言入口升级步骤](desktop-poll.md#已有项目启用自然语言入口) 使用 `refresh-project`。

导入要求原配置是 `desktop_poll` 且包含企微机器人。策略根与本机已经信任的旧策略不一致时会拒绝迁移。旧成员尚未导入签名版本前，不应混用旧客户端处理新增成员的任务。

## 首次验收

管理员和成员都绑定对话并完成实际轮询后，在群里选中实际机器人发送一条**新任务**：

```text
@Alice 给登录页增加密码显示切换，保持原有登录行为。
你做前端，Bob 补接口和测试，完成后在群里告诉我。
```

默认验收顺序：群回复需求 N-ID → Alice 对话理解需求并在群里确认任务 T-ID 与分工 → Alice 指定对话执行 → 群收到阶段总结、代码提交、测试和审核提示 → Alice 本人审核通过 → Bob 指定对话从获准的 SHA 接力 → Bob 本人审核最终结果 → 管理员完成任务。

需求不清时机器人先追问，直接 @同一个机器人补充；有多条待补充需求时带上 N-ID。状态问题或闲聊可以只回答，不创建任务。审核时指定审核人可直接 @自己的机器人说“通过，继续下一步”，或“先别通过，请补充键盘操作和相关测试”。有多条待审核任务时先选择名称、编号或任务 ID；只有一条时无需写 ID 或 R-版本号。含糊或带条件的决定先澄清，退回须有具体修改意见。完成、取消仍使用管理员命令。

管理员也能通过已经允许群命令的成员机器人创建/查询任务。`@Bob 协作 创建 ...` 默认使用 Bob 接入包中的首个职责；实际领取仍由能力路由、占用和候补决定。审核由当前指定审核人通过自己的机器人发出；完成、取消、重试仍需管理员通过自己的机器人发出。成员机器人不会代签其他人的操作。

```text
@Alice 协作 状态 T-实际任务ID
@Alice 协作 审核 T-实际任务ID R-7 通过
@Alice 协作 审核 T-实际任务ID R-7 退回 | 请补充键盘操作和相关测试
@Bob 协作 审核 T-实际任务ID R-12 通过
@Alice 协作 完成 T-实际任务ID
```

上面的精确命令继续兼容；示例中的 `R-7`、`R-12` 要替换成最新审核通知中的真实版本号。自然语言审核则固定收到消息时的版本，不能用旧消息批准后续提交。所有成员须先升级并重启 Runner/MCP、刷新 Skill 和原 heartbeat，旧客户端不能读取新审核记录。退回后当前阶段从被退回的 SHA 重做，对话会收到修改意见；重新提交后须使用新的版本号，旧命令会被拒绝。需要审核的阶段没有通过前，下一位不会接单。若关闭某职责的中间审核，中间提交直接交接；该职责作为最后阶段时仍交给管理员审核。

群通知会列出真人姓名对应的成员名称，并尝试带上已验证 userid 的提及。智能机器人长连接原生 @ 是否实际弹出提醒需要实群检查；加密 userid 转明文需要另接企业应用，目前没有集成。请同时检查群通知正文，不能仅以是否收到 @ 提醒判断任务是否在等待审核。

群里“任务已创建”和“机器人已认证”不能代替 Codex 已接单证据。最终任务不会自动批准或合并业务基准分支；管理员需要检查代码、真实测试证据再决定如何合并。消息中的 `npm test 通过` 是验收描述，真正运行的是管理员确认并固定的程序与参数（内部存为 argv）。

## 一个人使用多个机器人，或模拟两个同事

准备同一业务仓库的两个独立 clone、两个企业微信机器人和两个 Codex 对话。管理员给自己增加 Agent 可以直接在同一工作台完成：

1. 以 Alice 初始化团队，完成群验证并进入管理员项目。已有团队可直接打开已就绪的管理员项目。
2. 在项目页点击“添加我的机器人”（或“团队与邀请”中的“给自己增加机器人”），确认独立项目目录并填写新 Agent 名称 `bob`、职责 `backend`，点击“继续”，再填写新机器人的 Bot ID/Secret。
3. 保留“首选执行者”时，Bob 成为 backend 首选；Alice 若也有 backend 能力则是候补。点击“连接机器人”。无需包密码或下载接入包。
4. 用初始化 Alice 时的**同一个企业微信账号** @Bob，发送页面验证码，页面自动继续。工具校验本人身份，自动签名批准新 Agent、配置 Bob 项目的 MCP/Skill 并启动连接。Bob 仍是 member，不会继承 Alice 的管理员角色。
5. 在 Alice clone 和 Bob clone 中分别打开要绑定的已有 Codex 对话，向各自对话粘贴该项目的“启用指令”。每个 Agent 各自创建 heartbeat，确认身份与最近轮询。
6. 在群里 @Alice 创建包含两种职责的任务，例如 `[frontend>backend]`。默认 Alice 阶段提交后你 @Alice 审核，Bob 阶段提交后你 @Bob 审核，最后 @Alice 完成任务。以每次通知指定的审核身份和版本号为准。

两份配置都允许所有者发送群命令。同一个 userid 只表示是同一个真人；收消息的机器人决定签名 Agent，权限不会合并，发给 Bob 的管理员完成命令仍会被拒绝。审核人与通知对象属于同一个真人时，群通知只提及一次，同时列出所对应的 Agent 和必须使用的审核机器人。

普通团队成员拥有多个机器人时，由管理员给他分配多份独立接入包；成员用自己的同一个账号验证，管理员逐个确认，其余操作与成员流程一致。“给自己增加机器人”的自动批准入口仅供已经验证、就绪的管理员使用。

接入中断时，从管理员项目“已分配的机器人”找到 Bob，点击“继续接入我的机器人”，或从首页打开已经保存的 Bob 项目继续。不要重新生成同名 Agent。若误选 Alice 的 clone、另一个 remote 或已分配的 Bot ID，工具会拒绝。

使用这个功能前，所有参与者需运行包含多 Agent 所有权支持的新工具，并重启旧 Runner/MCP。旧客户端会拒绝重复 owner userid 或新邀请的可选字段。旧策略里没有 userid 的通知机器人仍按旧规则由管理员审核；已签名的旧身份绑定不能直接手改成新绑定。

## 工作台、停止和恢复

默认本机数据位于 `~/.config/codex-collab/workspace`，机器人 Secret、私钥、对话 ID、Runner 日志和接入状态均在业务仓库之外；私有 JSON 使用 `0600`。Git 只同步签名协议、公钥、职责、任务证据和必要结果摘要。

- 重复导入同一接入包：已验证或已接入的成员会直接打开原项目，继续原进度；不会重复启动群验证。
- 项目接单状态：同时检查 MCP、Skill、认证连接、目标对话绑定和最近三分钟内实际轮询。配置文件存在不等于 Codex 已加载，自动化启用状态仍需在绑定对话确认。
- 群验证断线/过期：点击“重新连接”，使用新的验证码。接入进度保存于本机，页面刷新能恢复原验证码；工作台进程重启后临时连接失效，会重新连接。
- 管理员群验证尚未完成：从首页“待完成群验证”打开“继续创建团队”，恢复保存的创建资料。
- 管理员丢失旧接入包密码：按[接入包密码遗失](#接入包密码遗失)重新签发；不要尝试从旧加密文件读取或猜测密码。
- Git/MCP 配置中断：从“我的项目”打开原项目，若显示错误，处理后点击“继续接入”；不要反复创建另一身份。
- 管理员生成邀请时网络失败：回项目页面刷新已生成接入包，再下载；本人机器人点击“继续接入我的机器人”。工具重试发布同一签名邀请。
- 本机工作台关闭：重新运行 `codex-collab setup`；已启动的机器人 Runner 会继续运行。
- 页面“停止机器人连接”只断开群机器人。暂停接单需在对应 Codex 对话暂停 heartbeat；已有任务仍需完成、报告失败或按租约恢复处理。
- CC Switch 与模型账号设置保持原样；项目 MCP 使用本机 Node 的绝对执行路径。

底层诊断命令仍可用，配置路径可在机器人的接入详情中展开“查看本机配置路径”并复制：

```sh
codex-collab status /absolute/path/to/private-peer.json
codex-collab doctor /absolute/path/to/private-peer.json
```

Secret 若曾发到聊天或 Git，应在企业微信重新生成后更新本机配置。工具只发布协作任务的阶段总结，不会把整个私有 Codex 对话发到群里；目前尚无任意普通对话完成后自动发群总结的独立工具。

旧命令兼容：`codex-collab setup --terminal` 或 `setup --role admin|member` 继续使用 [旧终端工作流](terminal-onboarding.md)，不走加密包与动态签名入队。

网页向导的逐项覆盖、故障恢复与功能遗漏见 [功能检查与测试记录](onboarding-audit.md)。

## 只连接自己的 Codex 会话

首页“连接我的 Codex”提供三步指引：选项目、连企微机器人、将启用指令发给目标 Codex 会话。先单人使用即可，团队名称、职责标签与邀请同事不必提前设置。有项目时，在首页“接入指引与其他方式”也能打开这份指引；已有接入直接打开项目中自己的机器人继续绑定，换会话则使用“管理与重置 → 重新绑定对话”。

此入口复用现有项目与任务机制，仍需可访问远程的 Git 仓库、API 模式企微智能机器人，以及在目标会话启用协作定时轮询。机器人认证、绑定和实际轮询都满足后才能处理群消息；MCP 本身不会自动唤醒空闲会话。

## 管理、重绑与移除本机接入

从首页打开项目，再打开自己的机器人，展开“查看连接详情 → 管理与重置”。操作会先展示当前 Agent、clone、对话 ID 和影响。重新绑定对话需输入 Agent 名称并确认原对话已暂停协作 heartbeat；移除本机接入则采用“查看影响 → 确认移除”两步，无需手动备份 Skill、输入名称或暂停轮询。移除会解除本机绑定，但不会删除 Codex 聊天。

**重新绑定对话**保留成员私钥和机器人配置，停止 Runner 并清除本机对话绑定及轮询观察状态。复制项目页面的启用指令到目标对话，完成绑定后启动连接。旧对话的轮询因绑定失效无法再领取任务。

**更新机器人凭据**只修改当前 Bot ID 的 Secret。点击“验证新凭据”后，向导先停止原连接，再临时连接机器人；用原绑定本人账号在原协作群发送验证码。验证和确认成功后同步当前 Runner/MCP 实际使用的私有配置，并保留对话绑定。点击“启动机器人连接”恢复。取消验证会关闭临时连接，原配置不变，Runner 不会自动重启。

**移除本机接入**用于当前 clone 重新接入或换身份。清除对话绑定、停用旧私有配置，仅移除本机协作 MCP 区块与 Skill，保留其他配置和业务文件。自定义 Skill 会自动写入权限受限的本机恢复记录，之后一并移除；恢复本机接入时可还原。未完成接入的项目也可移除。首页“已移除的接入”可以恢复原成员身份；已绑定其他身份的 clone 会阻止恢复，避免覆盖新接入。恢复不会恢复旧对话绑定或启动 Runner。

如果要换平台机器人、群或成员本人，先移除本机接入，再由管理员提供正确的新 Agent 接入包并按加入流程验证。移除不会撤销团队签名策略中的旧成员，管理员应另行管理分工；同一 Agent 不能通过重新初始化获得另一个已批准私钥。

重置预览有效期为十分钟。绑定、任务或文件变化后需重新预览；空闲轮询不会影响新 Secret 的群验证。当前 Agent 有有效任务租约时会拒绝重置，需先结束本阶段或在原对话报告失败；Git 无法访问时也不强行清理。自定义协作 Skill 会先自动存入本机恢复记录，确认后随接入移除，恢复时可还原；自定义 MCP、Git 已跟踪配置或符号链接仍会阻止自动移除，以免改动项目共享配置。

操作前的私有备份位于向导配置目录的 `reset-backups/`，完成提示会显示完整路径。它可能包含私钥、旧 Secret 与本机任务信息，权限为 `0600`；目录权限为 `0700`，不要分享或提交。业务代码、共享任务分支、未提交改动和任务 worktree 保留。页面“移除”提供可恢复的解绑，并非清除所有私人数据；不再需要恢复时按本机配置路径自行清理备份与旧身份。

## 0.5.0 后台连接与排查

首次使用推荐 `codex-collab setup`；直接运行 `codex-collab` 也会打开同一个向导。首页“连接我的 Codex”直接进入项目选择；选中已接入的本机目录会直接打开原连接，只读取本机记录后展示，避免重复输入机器人凭据和创建配置。首次在项目目录运行会带入项目路径与本机显示名称。团队名称、内部身份与职责标签收在更多设置中，仍需确认适合项目的验证命令。

邀请文件和密码填好后点击“继续”，下一屏展示成员、职责与项目。默认拉取到推荐目录；可以留空目录直接接入，也可以选择已有独立 clone。给自己增加机器人同样支持自动拉取独立目录。

后台工作台与浏览器生命周期独立。macOS 使用 LaunchAgent；Linux 使用 systemd 用户服务。服务保留启动时的 Node 路径和 PATH，升级或更换 Node 安装位置后可运行 `codex-collab autostart on` 更新。自启注册失败会显示说明，当前会话仍尝试使用独立后台进程。Windows 暂时只支持独立后台进程。

每 15 秒检查已开启的机器人进程。恢复失败按 15、30、60 秒等间隔退避，最长五分钟；机器人 SDK 本身处理连接重试。主动停止、移除、重置后的接入不会被恢复。0.4.x 的离线连接不会被迁移为自动启动。

在业务项目目录执行 `codex-collab doctor`，或在页面点击“检查整条连接”，可以看到每个环节与处理办法。此检查读取真实状态并测试 Git 推送权限，不创建或执行业务测试任务；它不能证明未来的 Codex 自动化一定唤醒对话。`codex-collab repair` 更新受管理的项目 MCP 与 Skill，恢复缺失 MCP 配置和 Skill；自定义或共享文件会拒绝覆盖。之后仍需重新加载 MCP。

`codex-collab status|start|stop|doctor|repair` 不再需要私有配置路径。多个接入时用 `codex-collab projects` 查看，再加 `--profile <项目ID>`；Agent ID 在本机唯一时也可使用。旧显式配置路径命令保留。向导、无路径 CLI 和登录后台服务统一使用当前系统用户的 `~/.config/codex-collab/workspace`，不随工作目录或 npm/源码安装位置变化。同一版本与构建复用同一个后台服务；代码或静态资源变化时，下次 `setup` 会升级后台服务。旧 `CODEX_COLLAB_HOME` 和内部服务 `--home` 参数不再切换真实数据目录。旧独立目录中的接入需迁移或导入，不能直接删除；不会自动扫描、合并不同身份。显式私有配置路径命令仍保留兼容。

`stop` 断开机器人并持久化停止意图；它不暂停 Codex 对话内的自动化。需要暂停整个协作时，还应在对应对话中暂停自动化。
