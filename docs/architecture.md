# 架构与范围

当前只支持企业微信。优先稳定企微的接入、收发、任务领取、交接和真人审核；其他 IM 的接入以后再评估。

## 推荐：本机 Peer 与网页向导

每位成员运行本机 Peer，通过自己的企业微信智能机器人接收群消息，将任务交给绑定的已有 Codex 对话。管理员在网页向导中配置项目、分配机器人并批准成员；同事导入加密个人接入包、验证企微身份并绑定对话。项目可以包含多个机器人，每个机器人保留独立身份与权限。

团队目录、任务与交接记录存放在业务仓库的 `agent-collab` 分支，以签名记录校验身份和操作；代码在独立业务分支流转。协作远程与基准分支由向导识别和确认，每个任务固定基准 commit。已有桌面对话依赖显式启用的轮询自动化领取任务，安装 MCP 或 Skill 本身不会唤醒对话。详见 [Peer 机制](peer.md)、[签名团队协议](team-registry.md) 和 [桌面对话轮询](desktop-poll.md)。

## 兼容：旧中心服务

旧模式从源码启动一个 HTTP/MCP 服务，由它维护 `agent-collab` 的独立 Git worktree，串行追加版本化任务事件。每位同事配置个人 MCP/Skill，按需运行 Runner；Runner 创建任务 worktree 和新的 Codex SDK 会话。代码在 `codex/task-*` 分支，任务事件在 `agent-collab` 分支。群消息只提供任务指令和状态摘要，不共享原始私聊记录。此模式由一个 Bot 代表不同账号发送消息，不提供多个独立机器人路由。

消息路径：企微群消息 → 群允许列表与 `wecom_userid` 身份映射 → 命令解析 → 服务权限检查 → Git 提交 → Bot 回复。任务路径：分配 → Runner 领取 → worktree 编码、提交与可信测试 → 审查 → 真人批准 → 管理员完成。只有明确属于当前企微群的任务才能通过群命令访问；历史未知通道数据保留原始来源，不自动转为企微任务。

旧中心服务只支持单实例写入，没有持久消息投递队列、租约、失败自动恢复或 Git push 冲突重放。默认监听 localhost；跨机器需配置 HTTPS 与访问限制。企微智能机器人使用出站 WebSocket，无需公网回调；认证成功与实际群收发需分别验证。旧模式操作见 [中心服务指南](legacy-center.md)，不与推荐的 Peer 接入步骤混用。
