# 团队安装与首次接入

管理员统一创建企业微信机器人、分配职责，再把加密个人接入包交给同事。成员不需要自行创建机器人、手工查群 ID/用户 ID，也不需要单独部署中心服务。每个人的本机工具直接通过共同的 Git remote 协作。

## 每个人先准备一次

1. 安装 Node.js 20+、Git 和支持对话 heartbeat 的 Codex 桌面应用。
2. clone 要协作的业务仓库。仓库需有 `origin/main`，本机 Git 凭据能读取并 push `agent-collab` 及任务代码分支。
3. 打开终端执行：

```sh
npm install --global xuym-codex-collab
codex-collab setup
```

网页自动打开；若未打开，执行 `codex-collab setup --no-open`，复制终端打印的本机链接。保留此终端以使用工作台。团队成员只需 clone 业务仓库，无需 clone 工具仓库。

同一台电脑模拟两位成员时，使用同一业务仓库的两个独立 clone、两个机器人、两个 Codex 对话；同一个 clone 只能接入一个身份。真正同事分别使用自己的电脑、企业微信账号和 Git 凭据。

## 管理员操作

1. 在企业微信创建独立智能机器人，获取 Bot ID 和 Secret，拉进协作群。为每位成员分别创建机器人并加入同一个群。
2. 工作台选择“初始化团队”：输入业务仓库本机目录、自己的成员名称、职责标签、固定验证命令，以及自己的机器人 Bot ID/Secret。成员名称与职责用英文、数字、下划线或连字符，例如 `alice`、`frontend,backend`。
3. 点击“连接机器人并验证群”，用自己的企业微信账号 @ 此机器人，发送页面显示的 `协作 接入 六位数字`。返回网页点击“已发送，继续检查”。工具自动发现群 `chatid` 与你的 `userid`，创建身份、签名账本和项目 MCP/Skill，并启动本机机器人 Runner。
4. 项目页面“分配机器人给成员”：填写成员名称、职责、成员机器人 Bot ID/Secret，以及至少 12 字符的接入包密码。“首选执行者”决定新成员在职责路由中排第一还是候补；未使用的职责会新增路由。
5. 生成并下载加密 JSON 接入包，交给指定成员；密码通过另一条可信渠道单独提供。包默认 7 天有效，同一成员或机器人不会同时分发多个有效邀请。
6. 成员完成群验证后，刷新“待确认的成员”，核对成员名称、职责和 userid，点击“确认此成员入队”。新的签名策略通过 Git 同步到其他在线成员，无需重建已有任务。
7. 管理员也按下文把自己的 Codex 对话启用。

机器人必须由一个本机 Runner 保持连接。同一个 Bot ID 不要同时运行旧服务、群发现命令和新 Runner。向导会检查可识别的本机重复连接；其他电脑上的连接需由团队自己核实。

## 成员操作

1. 从管理员取得自己的加密接入包和密码，先 clone 对应业务仓库。
2. 打开 `codex-collab setup`，选择“加入团队”。选择接入包文件、输入密码和业务仓库目录，点击“导入并连接机器人”。工具会核对 origin 仓库；允许同一 remote 的 SSH/HTTPS 表达，不会改写 origin。
3. 用**自己的企业微信账号** @ 分配给你的机器人，发送页面显示的验证码；回网页点击“已发送，继续检查”。本机生成签名身份，并把带公钥的入队申请写进协作分支。
4. 等管理员在自己的工作台确认，然后在项目页点击“继续接入”。工具检查 Git 权限、写入项目的本地 MCP 和 Skill、启动机器人连接。
5. 在 Codex 打开这个业务项目，信任项目并加载 MCP。工作台点击“复制启用指令”，粘贴到要代表你的**已有对话**，让对话完成身份核对、绑定真实 thread ID、创建 heartbeat 和首次无任务轮询。
6. 回工作台刷新状态，确认机器人认证、对话绑定、实际轮询均已观察到。

启用指令不是 Secret。成员无需手工编辑 JSON、生成密钥或复制 userid。Codex 若没有暴露真实对话 ID，仍需本人提供该对话 ID/链接；工具不会猜测或访问应用私有数据库。若应用不支持 heartbeat，页面的启用指令会要求明确报告限制，不能当作已自动接单。

向导看到一次或近期轮询，只证明 MCP 实际被调用过，不代表已读取到应用自动化的开关。完成绑定后也应在当前对话核对 heartbeat 是否启用。默认指令尝试一分钟；周期以应用工具实际接受并运行的结果为准。

## 已有 Alice/Bob 配置如何迁移

现有通过私有 `peer.json` 运行的项目无需重新生成身份或重绑对话。

1. 用原配置停止该机器人的 Runner：`codex-collab stop /absolute/path/to/private-peer.json`。有正在执行的任务时先处理其租约/执行状态。
2. 进入网页“导入已有配置”，填写原私有配置的完整路径。**旧团队由管理员先导入，然后其他成员分别导入**。
3. 工具从原策略建立签名版本根，保留原身份、私有数据目录、Codex 对话绑定和任务，再通过原配置路径重启 Runner。
4. 已有 heartbeat 可以继续使用原配置路径；仍在运行的 MCP 可重新加载以获取新版代码。以后统一在工作台查看状态、添加新成员。

导入要求原配置是 `desktop_poll` 且包含企微机器人。策略根与本机已经信任的旧策略不一致时会拒绝迁移。旧成员尚未导入签名版本前，不应混用旧客户端处理新增成员的任务。

## 首次验收

管理员和成员都绑定对话并完成实际轮询后，在群里选中实际机器人发送一条**新任务**：

```text
@Alice 协作 创建 [frontend>backend] 给登录页增加密码显示切换 | npm test 通过
```

验收顺序：群回复任务 ID → Alice 指定对话认领并执行 → 群收到阶段总结、代码提交和测试结果 → Bob 指定对话从同一交接 SHA 接力 → 所有阶段完成后等待真人审核。

管理员也能通过已经允许群命令的成员机器人创建/查询任务。`@Bob 协作 创建 ...` 默认使用 Bob 接入包中的首个职责；实际领取仍由能力路由、占用和候补决定。审核、完成、取消等操作由具有对应权限的真人通过自己的机器人发出，成员机器人不会替管理员签名审核。

```text
@Alice 协作 状态 T-实际任务ID
@Alice 协作 审核 T-实际任务ID 通过
@Alice 协作 完成 T-实际任务ID
```

群里“任务已创建”和“机器人已认证”不能代替 Codex 已接单证据。最终任务不会自动批准或合并 `main`；管理员需要检查代码、真实测试证据再决定如何合并。消息中的 `npm test 通过` 是验收描述，真正运行的是管理员在本机初始化时固定的 JSON argv。

## 一个人模拟两个同事

使用同一业务仓库的两个独立 clone、两个企业微信机器人和两个 Codex 对话。先以 Alice 初始化团队，再给 Bob 生成接入包；生成 Bob 接入包时**取消勾选“允许成员在群里给自己的机器人发任务”**，避免同一个真人 userid 同时绑定两个群命令身份。Bob 仍可领取、执行任务和向群里通知结果。任务通过 `@Alice` 创建，并按职责路由到 Alice 或 Bob；两份配置各自绑定对应项目中的对话。

## 工作台、停止和恢复

默认本机数据位于 `~/.config/codex-collab/workspace`，机器人 Secret、私钥、对话 ID、Runner 日志和接入状态均在业务仓库之外；私有 JSON 使用 `0600`。Git 只同步签名协议、公钥、职责、任务证据和必要结果摘要。

- 群验证断线/过期：点击“重新连接”，使用新的验证码。
- Git/MCP 配置中断：从“我的项目”打开原项目，再点击“继续接入”；不要反复创建另一身份。
- 管理员生成邀请时网络失败：回项目页面刷新已生成接入包，再下载；工具重试发布同一签名邀请。
- 本机工作台关闭：重新运行 `codex-collab setup`；已启动的机器人 Runner 会继续运行。
- 页面“停止机器人连接”只断开群机器人。暂停接单需在对应 Codex 对话暂停 heartbeat；已有任务仍需完成、报告失败或按租约恢复处理。
- CC Switch 与模型账号设置保持原样；项目 MCP 使用本机 Node 的绝对执行路径。

底层诊断命令仍可用，配置路径可在项目页面展开“查看本机配置路径”并复制：

```sh
codex-collab status /absolute/path/to/private-peer.json
codex-collab doctor /absolute/path/to/private-peer.json
```

Secret 若曾发到聊天或 Git，应在企业微信重新生成后更新本机配置。工具只发布协作任务的阶段总结，不会把整个私有 Codex 对话发到群里；目前尚无任意普通对话完成后自动发群总结的独立工具。

旧命令兼容：`codex-collab setup --terminal` 或 `setup --role admin|member` 继续使用 [旧终端工作流](terminal-onboarding.md)，不走加密包与动态签名入队。
