# 网页向导功能检查与测试记录

检查日期：2026-10-13。对象是工具仓库中的网页向导源码，本记录对应 0.3.1 的发布前验证。

## 测试范围

使用独立的临时 Git 仓库、真实 Git 分支与签名协议、模拟企业微信连接进行验证。浏览器实际操作管理员与成员表单、文件下载/上传、状态与审核配置；自动测试覆盖接口鉴权、异常输入、任务接力、真人审核和失败候补。本次没有修改个人真实机器人凭据，没有停止原有 Alice/Bob Runner。

浏览器中的“已认证”由模拟连接提供。测试中的对话绑定和轮询通过执行器 API 产生，不能据此宣称已完成真实企业微信群、桌面对话自动唤醒和多台电脑的联合验收。

完整测试命令是 `npm test`，最终结果为 **108 passed, 0 failed**。新增加的页面事件测试运行实际交付的 `app.js`，使用最小 DOM 验证 API 调用顺序与恢复；它不能替代真实浏览器交互。本次已结合两种测试。

## 本次修复

1. 重复导入已接入成员的接入包时，按已有阶段打开项目，避免重复验证抢占 Runner；首次导入后连接失败也能看到已保存项目和重新连接入口。
2. 项目状态独立显示 MCP 与 Skill，并识别旧版生成的 desktop 配置。综合就绪要求项目配置、认证连接、绑定和最近三分钟内实际轮询同时满足。显式禁用 MCP 会显示未就绪。
3. 验证成功后页面加载失败，不再因为清空 pending 而报空对象错误；管理员中断恢复识别本次新建的项目，兼容规范化后的目录路径。
4. 中断接入与 Runner 启停错误转换成可恢复的安全中文提示；保存错误供刷新查看，成功后清理。
5. 缺失 Git `info/exclude` 时正常创建父目录与排除文件，失败时恢复原状。
6. 无效验证命令在连接前拦截；损坏接入包 JSON 有具体文件错误提示。

## 本人多机器人补充验证

新增 8 项多所有者/多 Agent 自动测试、3 项网页事件测试、1 项企业微信审核通知测试和 1 项网页接口鉴权测试。完整测试通过后，没有修改执行逻辑；本记录补充了验证范围与结果。

浏览器使用新建的临时 Git 仓库、模拟机器人连接和模拟 Runner 启停，实际填写第二个 clone、新 Agent 和机器人配置，验证群身份后完成本人入队、安装 MCP/Skill，并从管理员页面继续打开该配置。这里的 ready 表示向导完成配置；模拟 Runner 不构成真实群连接或桌面对话验收。浏览器截图保存于本机临时目录，未加入发布包。

本人邀请带有签名保护的可选 `owner_userid`，要求群验证账号与已验证管理员一致；接入记录沿用正常签名申请和管理员批准。邀请与恢复资料保存在仓库外的 0600 私有文件中。普通同事可以通过多份接入包使用同一个真人账号，但仍需分别验证和批准。新客户端接受旧邀请；旧客户端不识别新所有者字段或共享所有者策略，采用此功能前应统一升级并重启 Runner/MCP。

## 尚缺少的页面功能

| 功能遗漏 | 当前影响 |
| --- | --- |
| 更换机器人、轮换 Secret、变更群 | 只能按本机配置与企业微信端操作；向导没有维护入口 |
| 撤销邀请、禁用/移除成员、轮换签名身份 | 当前没有产品化入口；需要补签名协议、权限与历史兼容，不能仅删本机文件 |
| 修改既有成员职责、重排首选与候补 | 页面只展示已有分工；生成邀请时可以指定新成员优先级 |
| 缺失 MCP/Skill 的一键修复 | 当前能识别缺失，但现有 Skill、受版本管理的配置等需要检查；不会自动覆盖 |
| 确认 heartbeat 持续启用、切换绑定对话 | 页面能观察绑定与最近轮询；不能控制 Codex 自动化，切换需要对话工具解除旧绑定 |
| 页面内展示日志与详细 Git 诊断 | 当前只有安全错误提示、私有配置路径；详细日志仍需本机查看 |
| 多管理员配置冲突的页面引导 | 后端按版本拒绝过时保存；页面需要刷新重新设置，不会自动合并 |
| 页面刷新保留正在进行的管理员验证码步骤 | 管理员保存 profile 前的验证码状态在当前页面内存中；刷新需重新填写和验证；成员已导入的项目可从首页恢复 |

## 仍需联合验收的环境场景

- 两台不同电脑分别安装 npm 包，对同一远程仓库各自接入、绑定真实 Codex 对话。
- 真实企业微信群中创建任务、自动轮询启动执行、阶段总结、真人审核、下一位接力。
- 企业微信原生 @ 提醒效果，以及真实 WebSocket 断线/凭据轮换的提示和恢复。
- 应用退出、电脑休眠、heartbeat 暂停与网络恢复后，候补接管与旧执行者的租约隔离。

页面的“项目 MCP / Skill 已就绪”表示本机文件已配置，并非读取了 Codex 的实际加载状态。近期成功轮询是额外证据，仍不能保证未来自动化持续运行。Git 启动检查与任务执行中的 Git 失败属于不同时间点，初始化通过不代表未来的 push 永远成功。
